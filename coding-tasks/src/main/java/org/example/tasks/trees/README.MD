# Транспарант в лесу

https://coderun.yandex.ru/selections/algorithm-training-september-2025/problems/banner/description

## Описание задачи

Группа «Коллективные действия» проводит акцию «Лозунг» в лесу. Они подготовили транспарант с надписью «Я НИ НА ЧТО НЕ
ЖАЛУЮСЬ И МНЕ ВСЕ НРАВИТСЯ, НЕСМОТРЯ НА ТО, ЧТО Я ЗДЕСЬ НИКОГДА НЕ БЫЛ И НЕ ЗНАЮ НИЧЕГО ОБ ЭТИХ МЕСТАХ», квадрат длины
транспаранта составил `d`.

Акция проходит в лесу, в котором растут `n` деревьев с целочисленными координатами `x` и `y`. Транспарант можно натянуть между
парой деревьев, квадрат расстояния между которыми в точности равен `d`. Чтобы посетителям было интереснее, группа
планирует каждый день вешать транспарант между новой парой деревьев. Определите, сколько дней можно выбирать новую пару
деревьев для проведения акции.

## Формат ввода

В первой строке входного файла даны два целых числа `n (1 ≤ n ≤ 10^5)` — количество деревьев в лесу и `d (1 ≤ d ≤ 10^8)` —
квадрат длины транспаранта.

В следующих n строках записаны пары целых чисел `x_i, y_i (-10^8 ≤ x_i, y_i ≤ 10^8)` — координаты деревьев. Все точки
различны.

## Формат вывода

Выведите количество подходящих пар деревьев.

# Решение

Поиск соседей для каждой точки, лежащих на окружности радиусом `sqrt(d)`

Входные данные о координатах деревьев будем складывать в класс `Point(int x, int y)`. Для каждой точки нужно проверить расстояние от неё до кандидата в пару.

Решение "в лоб" с проверкой расстояния от каждой точки до всех соседних не подходит - сложность по времени `O(n^2)`.

Подходящее решение - ограничить количество кандидатов. Возьмём только кандидатов, принадлежащих окружности радиусом `r = sqrt(d)` и с центром в текущей точке. Так как координаты всех точек целочисленные и квадрат расстояния - целое число, мы можем найти допустимые смещения от текущей точки до кандидата `dx`, `dy`.

Метод `getAvailableDxDy` ищет допустимые смещения по теореме Пифагора: `d^2 = dx^2 + dy^2`. Перебираем целые значения `dx` от `0` до `r`. Так мы осмотрим только четверть окружности. Находим `dy^2`. Если `sqrt(dy^2)` даёт целое число, то пара `dx`, `dy` нам подходит. Добавим четыре пары смещений: `(dx, dy)`, `(dx, -dy)`, `(-dx, dy)`, `(-dx, -dy)`. Этот расчёт делается один раз, сложность `O(sqrt(d))`.

Все точки из входного потока сохраним в `HashSet`. Эта структура позволит проверять существование точек за `O(1)`.

Перебираем все входные точки и для каждой проверяем, существует ли по допустимым смещениям точка `HashSet.contains(Point)`. Если точка существует, увеличиваем счётчик.

При подсчёте пар могут появиться дубликаты: два раза посчитаем пары `(A - B)` и `(B - A)`. Для этого вводим дополительную проверку

`if (newX > point.getX() || (newX == point.getX() && newY > point.getY()))`

"смотрим только на четверть окружности".

Сложность перебора всех точек составит `O(n)`, общая сложность составит примерно `O(n * sqrt(d))`.
