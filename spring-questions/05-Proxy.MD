### Ответы

#### 1. Зачем Spring использует прокси
Spring использует прокси для реализации **AOP (Aspect Oriented Programming)**. Прокси позволяет "обернуть" бин и добавить дополнительную логику (транзакции, логирование, безопасность, кэширование) до или после выполнения основного метода, не изменяя исходный код класса.

#### 2. Какие бывают типы прокси (JDK Dynamic Proxy, CGLIB)
- **JDK Dynamic Proxy**: Стандартный механизм Java. Создает прокси-объект, реализующий те же интерфейсы, что и целевой класс.
- **CGLIB (Code Generation Library)**: Сторонняя библиотека (включена в Spring). Создает прокси-объект путем динамического создания подкласса целевого класса (наследование).

#### 3. Когда используется JDK Proxy
По умолчанию Spring использует JDK Proxy, если целевой класс реализует хотя бы один интерфейс.

#### 4. Когда используется CGLIB
CGLIB используется в следующих случаях:
- Если целевой класс не реализует ни одного интерфейса.
- Если в настройках Spring явно указано использование CGLIB (например, `proxy-target-class="true"`).

#### 5. Почему final методы не проксируются
- В **JDK Proxy** прокси реализует интерфейс, поэтому методы интерфейса переопределяются. Но если метод в целевом классе `final`, это не мешает прокси вызвать его (хотя логика прокси будет "снаружи").
- В **CGLIB** прокси является подклассом. Методы, помеченные как `final`, нельзя переопределить в наследнике, поэтому CGLIB не может добавить к ним свою логику.

#### 6. Почему final классы создают проблемы для прокси
Поскольку CGLIB создает прокси через наследование, он не может работать с `final` классами, так как от них нельзя наследоваться. В этом случае Spring не сможет создать CGLIB прокси.
