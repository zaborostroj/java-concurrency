### Ответы

#### 1. Что такое транзакция
**Транзакция** — это группа последовательных операций с базой данных, которая представляет собой логическую единицу работы. Она должна быть выполнена целиком или не выполнена вовсе.

#### 2. Свойства ACID
- **Atomicity (Атомарность)**: Гарантирует, что транзакция будет зафиксирована полностью или не будет зафиксирована совсем.
- **Consistency (Согласованность)**: Транзакция переводит БД из одного согласованного состояния в другое.
- **Isolation (Изолированность)**: Параллельные транзакции не должны влиять друг на друга.
- **Durability (Долговечность)**: Результаты успешно завершенной транзакции должны быть сохранены даже в случае сбоя системы.

#### 3. Как создать транзакцию в Spring
Наиболее распространенный способ — использование аннотации `@Transactional` над методом или классом. Также необходимо наличие бина `PlatformTransactionManager` и аннотации `@EnableTransactionManagement` (в Spring Boot включена по умолчанию).

#### 4. Как работает @Transactional внутри
Spring использует механизм AOP. Когда вызывается метод с `@Transactional`, Spring создает прокси-объект, который:
1. Открывает соединение с БД и начинает транзакцию.
2. Вызывает целевой метод.
3. Если метод завершился успешно — фиксирует (commit) транзакцию.
4. Если возникло исключение — откатывает (rollback) транзакцию.

#### 5. Почему @Transactional работает через прокси
Прокси позволяет "обернуть" бизнес-логику техническим кодом управления транзакциями, не засоряя саму бизнес-логику.

#### 6. Будет ли работать вызов Transactional-метода из другого метода того же класса
**Нет.** Поскольку `@Transactional` работает через прокси, вызов должен прийти извне бина. Внутренний вызов (`this.method()`) идет в обход прокси, и транзакционная логика не сработает.

#### 7. Когда происходит rollback (RuntimeException vs CheckedException)
По умолчанию Spring откатывает транзакцию только при возникновении **непроверяемых** исключений (`RuntimeException` и `Error`).
Для отката при **проверяемых** исключениях (`Checked Exception`) необходимо явно указать это в параметре: `@Transactional(rollbackFor = Exception.class)`.

#### 8. Propagation уровни (REQUIRED, REQUIRES_NEW, SUPPORTS, MANDATORY)
- **REQUIRED (по умолчанию)**: Если транзакция есть — используется она, если нет — создается новая.
- **REQUIRES_NEW**: Всегда создается новая транзакция. Если была текущая — она приостанавливается.
- **SUPPORTS**: Если транзакция есть — выполняется в ней, если нет — выполняется без транзакции.
- **MANDATORY**: Требует наличия текущей транзакции. Если ее нет — выбрасывается исключение.

#### 9. Isolation уровни (READ_UNCOMMITTED, READ_COMMITTED, REPEATABLE_READ, SERIALIZABLE)
- **READ_UNCOMMITTED**: Чтение незафиксированных данных (Dirty read).
- **READ_COMMITTED**: Чтение только зафиксированных данных.
- **REPEATABLE_READ**: Гарантирует, что повторное чтение тех же данных вернет тот же результат (защита от Non-repeatable read).
- **SERIALIZABLE**: Самый высокий уровень, транзакции выполняются последовательно (защита от фантомного чтения).

#### 10. Почему @Transactional может не работать
1. Метод не `public`.
2. Вызов метода внутри того же класса.
3. База данных или движок (например, MyISAM в MySQL) не поддерживают транзакции.
4. Исключение перехвачено внутри метода через `try-catch` и не выброшено наружу.
5. Аннотация стоит над методом, который вызывается в другом потоке.
